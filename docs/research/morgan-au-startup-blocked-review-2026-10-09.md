Two material findings prevent approval of the stated metadata-only, complete-error-retention design:

1. **Startup unconditionally accesses full live preset state and prepares DSP resources.** `scripts/au_render_server.swift:155` retrieves `unit.fullState` and its `jucePluginState` blob; lines 163–172 copy and decode that state, including its XML document. These actions execute before the readiness reply at lines 249–250, regardless of the commands Python sends. The Python command restriction therefore does not make this a metadata-only instance/version check under the requested no presets/data scope. State serialization and DSP allocation can also fail independently of instantiation/version retrieval, changing the question being tested. Provide a startup path that reports the component version without retrieving/decoding full state or doing render setup, and freshly review its pins before declaration. No claim is made here that allocation processes samples or that this source explicitly opens a preset file.

2. **Compiler/cache errors can disappear, allowing a successful result without complete error evidence.** `scripts/_swift.py:91–99` retries SDK alternatives after an SDK/compiler mismatch but returns only the final attempt. An initial nonzero compiler result and its stdout/stderr are discarded if a later attempt succeeds. `scripts/_swift.py:50–62` also catches cache-path/copy/setup `OSError` and falls back to compilation without returning the original error. The version probe at line 75 contributes text to a cache key but its return code and diagnostics are not retained as execution evidence. `scripts/check_morgan_au_startup.py:159–166` records only the returned build result, so none of those earlier diagnostics reach `compile.json` or the report. For example, an SDK mismatch followed by a successful alternative build, a valid startup reply and exit 0 can produce READY with no record of the original build failure. This conflicts with the frozen design's complete compile-output retention and its no-original-error/any-logged-error readiness rule. Retain all compiler attempts and cache fallback/probe diagnostics, and explicitly enforce the declared readiness treatment of those errors. Compiler SDK retries are separate from AU instance retries; there is only one AU launch in the checker.
