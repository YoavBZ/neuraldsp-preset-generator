# Security

## Reporting a vulnerability

Use GitHub's [private vulnerability reporting](https://github.com/YoavBZ/neuraldsp-preset-generator/security/advisories/new)
rather than opening a public issue. It is enabled on this repository.

## What this project touches

It reads and writes **Neural DSP preset files** on your machine, and it can talk
to an installed plugin through its Audio Unit interface. That means two things
worth knowing:

- **It writes into your preset library.** `apply_spec.py` refuses to overwrite
  without `--force`, and the preset folder is the one place where a silent
  overwrite destroys work you care about. Keep backups of presets you value.
- **The probes load and unload a plugin in your process** and set its state.
  They never render to an audio device and never write a file the plugin owns.
  They need macOS, and a licensed and installed copy of the plugin.

## What ships here

No Neural DSP code, audio, impulse responses, or factory presets — see
[NOTICE.md](NOTICE.md). The packs contain parameter names, kinds, ranges and
selector labels, all of which are facts about an interface rather than content.
The one committed preset (`samples/Example_Clean_PR12.xml`) was generated by
this project.

## Scope

This is a personal-interoperability tool with no network surface, no server, and
no credential handling. The realistic risks are local: a bad write to your
preset library, or a wrong parameter value reaching a plugin. Both are covered
by the verification the repo is built around — see
[docs/measuring-against-the-plugin.md](docs/measuring-against-the-plugin.md).
